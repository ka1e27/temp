# Hex Dominion 2 — Architecture & Contracts

This is the **how**. `docs/DESIGN.md` is the **what/why**. Data shapes in this file are
contracts between modules built by different engineers in parallel: implement them exactly,
and if you must change one, say so loudly in your final report.

---

## 1. Ground rules

- **Zero dependencies, no build step.** Vanilla ES modules (`import`/`export`), served as
  static files. Node ≥ 22 for tests and tools (built-in `node:test`, global `fetch`,
  `WebSocket`). Never add `package.json` dependencies.
- **All new code lives under `game/`.** The v1 game in `src/`, `tests/` and the old `tools/`
  scripts is legacy reference: never import from it, never edit it.
- **Pure directories:** `game/core`, `game/world`, `game/battle`, `game/meta` must not touch
  `document`, `window`, `localStorage`, `Math.random`, `Date.now`, `performance`,
  `requestAnimationFrame`, `fetch`, or `Audio*`. Inject time, randomness (seeded RNG from
  `game/core/rng.js`) and storage. This keeps the simulation deterministic and testable in
  Node.
- **Deterministic battles.** Same arena + params + command log ⇒ identical result. No
  randomness at all inside `game/battle` (map generation uses seeded RNG only).
- **JSON-serialisable state.** World data, game state and battle state are plain objects and
  arrays (no `Map`, `Set`, class instances or functions stored inside them). Build lookup
  structures at load time and keep them outside the saved object (e.g. a `WeakMap` cache or
  a separate "runtime" object).
- Style: 2-space indent, semicolons, single quotes, `const` by default, JSDoc typedefs on
  exported functions and shapes. Files ideally < 500 lines; split by responsibility.
- Tests: `node --test "game/tests/**/*.test.js"` (`npm test`). Use `node:test` and
  `node:assert/strict`. Tests must not need a browser.
- Browser tooling: `tools/cdp.js` drives a local Chrome via the DevTools protocol with no
  dependencies. On this machine set
  `CHROME_PATH="/c/Program Files/Google/Chrome/Application/chrome.exe"`. `npm start` serves
  the repo at `http://localhost:8080/`.

## 3. Hex conventions (`game/core/hex.js`)

- **Pointy-top** hexes, **axial** coords `(q, r)`, storage in an **offset "odd-r"** grid of
  `cols × rows`. Tile index `i = row * cols + col`.
- offset → axial: `q = col - (row - (row & 1)) / 2`, `r = row`.
- axial → offset: `col = q + (r - (r & 1)) / 2`, `row = r`.
- Pixel centre in **world units** (hex size = 1 = centre-to-corner):
  `x = √3 · (q + r/2)`, `y = 1.5 · r`. The renderer multiplies by its zoom.
- Axial neighbour directions (in this order):
  `[+1,0] [+1,-1] [0,-1] [-1,0] [-1,+1] [0,+1]` (E, NE, NW, W, SW, SE).
- Required exports: `offsetToAxial`, `axialToOffset`, `axialToPixel`, `pixelToAxial`
  (with cube rounding), `hexDistance`, `neighbors(q,r)`, `hexKey(q,r)` → `"q,r"`,
  `hexCorners(cx, cy, size)` → 6 points starting at the top vertex going clockwise,
  `ring(q,r,n)`, `spiral(q,r,n)`, `lineBetween(a,b)`.

## 4. World contract (`game/world/generate.js`)

`generateWorld(seed: number, opts?: { cols?, rows?, regionCount?, dynasty? }) → World`

Deterministic for a given `(seed, opts)`. Must run in < 300 ms in Node for the default size.
The world is **never saved**; it is regenerated from the seed on load.

```js
/** @typedef {'deep'|'ocean'|'shallows'|'beach'|'grass'|'meadow'|'forest'|'pine'|'hills'
 *   |'mountain'|'snow'|'savanna'|'desert'|'marsh'} Terrain */

World = {
  seed, cols, rows,
  tiles: Tile[],              // length cols*rows, index = row*cols + col
  regions: Region[],          // index = region id
  settlements: Settlement[],  // index = settlement id
  factions: Faction[],        // index = faction id (0 player, 1 Free Folk, 2..4 rivals)
  startRegion: number,        // region id the player starts with
  bounds: { minX, minY, maxX, maxY },   // world-unit bounding box of LAND tiles
}

Tile = {
  i, col, row, q, r,
  x, y,                       // world-unit pixel centre (see §3)
  terrain: Terrain,
  elev: 0|1|2|3,              // 0 water, 1 lowland, 2 hills, 3 mountain (render height)
  height: number,             // raw 0..1 elevation noise (for shading variety)
  moisture: number,           // raw 0..1
  land: boolean,              // false for deep/ocean/shallows
  passable: boolean,          // land && terrain !== 'mountain'
  cost: number,               // movement cost (Infinity if !passable), road already applied
  road: number,               // bitmask of neighbour directions (bit d = road to neighbour d)
  river: number,              // bitmask of neighbour directions the river flows to/from; 0 = none
  coast: number,              // bitmask of neighbour directions that are water (land tiles only)
  region: number,             // region id, or -1 (water / islets / unassigned)
  settlement: number,         // settlement id, or -1
  jitter: number,             // stable 0..1 per-tile random for visual variety
}

Region = {
  id, name,
  tiles: number[],            // tile indices (all land, all passable-or-mountain)
  neighbors: number[],        // adjacent region ids (sharing an edge)
  centroid: { x, y },         // world units, for labels/camera
  bbox: { minX, minY, maxX, maxY },
  keep: number,               // settlement id of the region's keep
  settlements: number[],      // all settlement ids in the region (includes keep)
  tier: number,               // 0 = start region, 1 = adjacent, ... (BFS over neighbors)
  faction: number,            // ORIGINAL owner faction id (player owns startRegion = 0)
  isCapital: boolean,         // faction capital (rival factions only)
  biome: Terrain,             // dominant terrain
  perk: string,               // perk id (see DESIGN §3.5): 'fertile'|'timber'|'iron'|'stone'
                              //   |'horses'|'harbour'|'shrine'|'throne'
  coastal: boolean,
}

Settlement = {
  id, tile, region,
  type: 'hamlet'|'village'|'town'|'fort'|'tower'|'keep',
  name: string,               // generated; keeps share their region's name
}

Faction = {
  id, name, color, colorDark, colorLight, emblem: 'star'|'wheat'|'sword'|'eye'|'sun',
  personality: 'player'|'passive'|'aggressive'|'defensive'|'swarm',
  capitalRegion: number,      // -1 for player/Free Folk
}
```

Generation guarantees (tested):
- Exactly one connected playable landmass; every region's tiles are contiguous; the region
  adjacency graph is connected.
- Every settlement sits on a passable tile; settlements are ≥ 3 hexes apart; every pair of
  settlements in a region is connected by a passable path that stays inside the region.
- Every region has exactly one keep. Start region is coastal and near the map edge.
- Tier 1 regions and most tier 2 regions belong to Free Folk (faction 1); faction sectors are
  contiguous; each rival faction has exactly one capital, at its sector's max tier.
- Roads connect all settlements within each region (MST over A* paths) and each keep to the
  keeps of neighbouring regions; road tiles get cost 0.55 (before river penalty).

## 5. Game state contract (`game/meta/state.js`) — the save file

```js
GameState = {
  version: 1,
  seed: number,               // world seed for the current dynasty
  dynasty: { level: 1, stars: 0 },
  gold: number,
  owner: number[],            // owner faction id per region id (initialised from world)
  conqueredAt: (number|null)[],   // ms timestamp per region, null if not conquered by player
  crowns, metFactions, intel, prosperity, works,   // per-continent feature state (reset by a new dynasty); see their meta/*State.js leaves
  upgrades: { [upgradeId]: number },  // levels, missing = 0
  stats: { battlesWon, battlesLost, regionsConquered, goldEarned, troopsSent,
           settlementsTaken, bestBattleSec, playSec, surrenders, crownsEarned },
  chronicle: Chronicle,       // the realm's story (meta/chronicleState.js); lifetime state, kept by a new dynasty
  settings: { sound, reduceMotion, reduceMotionSet, hints, speed (0.5|1|2|3), slowBattles, leaderVoices, music, musicVolume, sfxVolume },  // whitelisted and clamped on load
  saveSeq: number,            // rises with every write: two tabs must not overwrite each other (app/autosave.js)
  tutorial: { seen: { [stepId]: true }, done: boolean },   // a set of seen steps (W0..M4); an old { step, done } save is migrated by save.js
  lastSeen: number,           // ms timestamp of last save (for offline earnings)
  battle: BattleState | null, // in-progress battle, for resume
}
```

Pure API (all take `now` explicitly where time matters):
- `createGame(seed, world, now)`; `incomePerSec(state, world)`; `tickIncome(state, world, dtSec)`;
  `offlineEarnings(state, world, now) → { seconds, gold }` (capped by Treasury);
- `upgradeCost(id, level)`, `canBuy(state, id)`, `buy(state, id)`; `UPGRADES` definitions
  (id, tab, name, icon, desc, `effectText(level)`, cost curve, max level or none);
- `playerBattleStats(state, world) → PlayerStats` (see §6) combining upgrades, perks, stars;
- `enemyBattleStats(world, state, regionId) → EnemyStats`;
- `frontier(state, world) → regionId[]` (not owned, adjacent to owned);
- `revealed(state, world) → boolean[]` per region (owned or adjacent to owned);
- `conquer(state, world, regionId, now) → { bounty, perk }` (applies decapitation);
- `difficulty(state, world, regionId) → { power, strength, ratio, label, surrender }`;
- `canFoundDynasty(state)`, `foundDynasty(state, newSeed)`;
- `save.js`: `serialize(state) → string`, `deserialize(string) → GameState` (validates,
  migrates by `version`), `exportCode(state)`, `importCode(str)`; storage is injected:
  `saveTo(storage, state)`, `loadFrom(storage)` with key `'hexdominion.v2'`.

## 6. Battle contract (`game/battle/*`)

```js
PlayerStats = { atk, def, growth, speed, campTroops, garrisonShare, capBonus,
                cooldownMult, powers: { rally: lvl, firestorm: lvl, bulwark: lvl,
                march: lvl, levy: lvl } }      // lvl 0 = locked
EnemyStats  = { atk, def, growth, speed, troopMult, thinkSec, personality, factionId }

Arena = {
  regionId, enemyFaction,
  tiles: [{ i, q, r, x, y, cost, terrain, region }],  // passable tiles only
  sites: [{ id, settlement, tile, type, owner, troops }],
        // id: 0..n-1 (index in this array); settlement: world settlement id or -1 (camp)
  focus: { minX, minY, maxX, maxY },  // world units, for camera framing
}
```

- `buildArena(world, owners: number[], regionId, player: PlayerStats, enemy: EnemyStats)
  → Arena` — includes the target region's passable tiles + player-owned passable tiles
  within 4 hexes; places the War Camp; sets starting troops.
- `createBattle(arena, player, enemy, opts?) → BattleState`
- `step(battle, dt)` — advances by `dt` seconds (the loop calls it at fixed 0.05 s);
  clears then fills `battle.events`.
- `issue(battle, command)` — commands are queued in `battle.commands` and applied at the
  start of the next `step`, so a command log replays deterministically:
  - `{ type: 'send', owner, from: siteId[], to: siteId, fraction }`
  - `{ type: 'power', owner, power: 'rally'|'firestorm'|'bulwark'|'march'|'levy',
       target: siteId | { q, r } | null }`
- `squadPosition(battle, squad, alpha?) → { x, y }` world units (for rendering/interp).
- `previewSend(battle, from[], to, fraction)` → predicted arrival counts & outcome if
  nothing else changes (used for the drag tooltip).
- `estimateDifficulty(arena, player, enemy) → { power, strength, ratio }` (fast, no sim).

```js
BattleState = {
  version: 1, t: number, tick: number, speed: 1,
  arena: Arena,                         // kept so a saved battle is self-contained
  player: PlayerStats, enemy: EnemyStats,
  sites: [{ id, tile, type, owner, troops, cap, growth, def,
            bulwarkUntil: 0, assault: null }],
  squads: [{ id, owner, count, from, to, path: number[] /* tile indices */,
             seg: number, prog: number, state: 'march'|'fight'|'assault',
             foe: number|null }],
  cooldowns: { rally: 0, firestorm: 0, bulwark: 0, march: 0, levy: 0 },
  effects: { marchUntil: 0 },
  pending: [ /* delayed effects, e.g. firestorm impacts {at, q, r, owner, power} */ ],
  ai: { nextThink: number, memo: {} },
  commands: [], events: [],
  result: null | 'win' | 'lose' | 'retreat',
  stats: { sent, lost, killed, captured, durationSec },
  nextId: number,
}
```

Events (`battle.events`, consumed by render/fx/audio/UI each frame; positions in world units):
`send {owner, from, to, count, squad}` · `clash {x, y, a, b}` · `clashEnd {x, y, winner}` ·
`assault {site, owner}` · `capture {site, from, to, x, y}` · `arrow {site, squad, x1, y1, x2, y2}` (a tower's, or the War Camp's with Watchtower Works) ·
`supply {owner, from, to}` · `unsupply {owner, from, reason: 'removed'|'lost'}` · `refused {reason: 'noRoute', owner, to}` (`send` carries `auto: true` for a supply line's own sends) ·
`power {owner, power, x, y, target}` · `firestorm {x, y, radius}` · `surrender {sites: []}` ·
`end {result}`.

## 7. Rendering (browser only)

- One full-screen canvas `#world`, device-pixel-ratio aware (cap DPR at 2).
- Camera: `{ x, y, zoom }` = world-unit point at screen centre and pixels per world unit.
  `worldToScreen`, `screenToWorld`, animated `flyTo(bounds|point, zoom, ms)`, clamped pan.
- **Terrain cache:** the static terrain (tile tops, skirts, decorations, rivers, roads, coast
  foam) is rendered into offscreen canvases in **chunks** (e.g. 8×8 tiles) at a quantised
  zoom level and blitted each frame; re-rendered lazily when the quantised zoom changes.
  Never redraw every hexagon every frame.
- Draw order per frame: ocean background → terrain chunks → territory tint + borders →
  cloud shadows → settlements (sprites cached per type/owner/zoom bucket) → banners
  (animated) → squads → projectiles/fx → clouds over hidden regions → labels/badges.
- Sprites and tiles are pure drawing functions `(ctx, x, y, size, opts)` in
  `render/sprites.js` and `render/tiles.js`; caching is the renderer's job.
- Everything animated uses the frame time passed in; nothing in `render/` mutates game or
  battle state.

## 8. UI (DOM, browser only)

- All UI lives in `#ui`, absolutely positioned over the canvas. Components are functions that
  build DOM from data and return `{ el, update(data), destroy() }`. No framework.
- `ui/dom.js` exports `h(tag, props, ...children)`; `ui/icons.js` exports `icon(name, size)`
  returning an inline SVG element.
- Pointer events: the canvas receives map input; UI elements stop propagation. The `#ui`
  root is `pointer-events: none`; each panel sets `pointer-events: auto`.

## 9. Frame loop (`game/main.js`)

- `requestAnimationFrame` loop with real `dt` (clamped to 0.25 s).
- Idle income always accrues on wall-clock time (never scaled by battle speed).
- Battles step at a fixed 0.05 s timestep × speed, with an interpolation alpha for rendering.
- Events are drained once per frame after stepping and fanned out to fx, audio and UI.
- Autosave every 5 s and on `visibilitychange`/`pagehide`.

## 10. Concurrent battles and the Living Frontier (contract, round 4)

Design: DESIGN.md §10. This is the contract both the sim side and the integration side build
against. Names are binding unless the lead agrees a change.

### 10.1 Battles move out of the scene
Today `game/scenes/battle.js` owns the sim loop for one battle in `state.battle`. From now on:
- **`game/app/battles.js`** owns every running battle. It is created once in `main.js`:
  `createBattleManager({ getState, getWorld, services }) → manager`.

  | Method | Behaviour |
  |---|---|
  | `list()` | every running `BattleRun` |
  | `get(id)` | one `BattleRun` |
  | `focused()` | the `BattleRun` being watched, or null |
  | `focus(id)` | sets the watched battle; null means the map |
  | `start(run)` | adds a `BattleRun`; refuses beyond `FRONTIER.maxBattles` (3) or on a busy region |
  | `tick(dtSec)` | fixed-steps EVERY running battle at the global speed (see below) |
  | `retreat(id)` | retreats that battle |
  | `setAuto(id, bool)` | hands that battle to its steward, or takes it back |
  | `setSpeed(s)`, `setPaused(b)` | global; apply to all battles |
  | `busy()` | `{ regions: Set, sites: Set<"regionId:settlementIdx"> }` of everything engaged |
  | `on(event, fn)` | subscribe to manager events |

  Manager events:

  | Event | Payload |
  |---|---|
  | `'events'` | `(runId, battleEvents)`, every step |
  | `'ended'` | `(runId, result)` |
  | `'started'` | `(runId)` |
  | `'focus'` | `(runId)` |

- **Per tick, for each run:**
  - `think()` for the enemy side.
  - For the player side: if the run is focused and not on auto, the player's own input (via
    the scene); otherwise `stewardDecide()`.
  - `step()` at `TICK_SEC`.
  - Drain events: fx and sfx only for the focused run; toasts and the tray for all runs.
- **On `'ended'`:**
  - attack won → `conquer` + crowns + chronicle (as today)
  - attack lost or retreated → nothing
  - defense won → `defenseReward`
  - defense lost → `occupy`
  - Then the run is removed and its General freed (or wounded, in Phase 2).
- **The battle scene becomes a view** of `manager.focused()`: render, input and HUD. Switching
  is `manager.focus(id)` plus a camera flight. The world scene stays usable while battles run.
  Battles keep running when no battle is focused.
- **Speed and pause** are manager-global. Idle income stays on wall-clock time.

### 10.2 State (plain JSON; `save.js` sanitises everything, `resetRegions` resets per-dynasty fields)

`state.battles: BattleRun[]` replaces `state.battle`. A legacy `state.battle` migrates into a
one-element list.

`BattleRun` fields:

| Field | Meaning |
|---|---|
| `id` | from `state.frontier.seq++` |
| `kind` | `'attack'` or `'defense'` |
| `regionId` | the region fought over |
| `fromRegionId` | defense only: the attacking region |
| `attackerFaction` | defense only |
| `battle` | the sim state (as today, including `crownTracker`) |
| `commander` | generalId or null |
| `auto` | boolean |
| `startedAt` | wall ms |

`state.frontier` fields:

| Field | Meaning |
|---|---|
| `seq` | id counter |
| `rng` | a seeded counter |
| `activeSec` | active-play seconds this dynasty |
| `nextCheckAt` | when the raid scheduler next looks |
| `cooldown` | `{ [regionId]: untilActiveSec }` |
| `incoming` | `[{ id, faction, fromRegionId, toRegionId, arriveAt, strength }]` |
| `lastAwayReport` | the most recent away report |

The other new state:
- `state.occupation`: `{ [regionId]: { by, at, prosperity, forts, works, militia } }`. While
  occupied, `state.owner[regionId]` is the occupier's faction id.
- `state.forts`: `{ [regionId]: [{ type, level }] }`, the fortifications.
- `state.militia`: `{ [regionId]: { fill: 0..1, at: ms } }`, refilled lazily from the time.

### 10.3 Sim (pure, `game/battle/*`, owned by the sim engineer)
- `buildDefenseArena(world, owners, regionId, opts) → arena`, with `arena.mode = 'defense'`.
  - `opts` = `{ attackerFaction, fromRegionId, player, enemy, forts, militia, busy }`.
  - **Player sites:** the region's settlements with their militia garrisons, plus fortification
    sites (Arrow Towers as tower sites; Walls multiply keep and fort defence; Militia Hall
    raises garrisons; Beacon adds speed).
  - **Enemy:** a war-band camp on their border tile nearest your keep, plus partial garrisons
    of adjacent enemy settlements.
  - Front lines and `busy` exclusion apply.
- `createBattle(arena, player, enemy, { mode, siegeSec })`, with `mode: 'defense'`:
  - `result 'win'` when `battle.t ≥ siegeSec` with your keep held, or when the attackers have
    no sites or squads left in the arena
  - `'lose'` when the enemy captures your keep; the surrender cascade goes to the enemy
- `stewardDecide(battle, t, memo, style) → commands` (`game/battle/steward.js`): the
  player-side defensive policy of DESIGN §10.6. Styles are `'captain'`, `'stalwart'`,
  `'bold'`, `'cunning'` and `'swift'`; Phase 1 needs `'captain'` plus one good default.
- `buildArena(...)` (attack) gains `opts.busy`, so busy sites and regions are excluded from
  the halo.
- `estimateDefense(state, world, regionId, raid) → { winChance, label, theirs, yours }` for UI
  labels.

### 10.4 Meta (pure, `game/meta/*`, owned by the sim engineer)
**`frontier.js`:**
- `tickFrontier(state, world, nowMs, activeDt) → { announced: [raid], arrived: [raid] }`. It is
  seeded and deterministic, and respects grace, rates, caps and cooldowns (DESIGN §10.1).
- `defenseRunFor(state, world, raid, stats) → BattleRun`.
- `defenseReward(state, world, run, result) → { gold, renown }`. Renown lands in Phase 2;
  return 0 until then.
- `occupy(state, world, regionId, faction, nowMs)`: freezes prosperity, moves forts and works
  into `occupation`, and sets the owner.
- `retake(state, world, regionId, nowMs)`: restores everything; called from `conquer` when the
  region is in `occupation`.
- `resolveAway(state, world, awayMs, nowMs) → report`: the abstract, gentle away rules of
  DESIGN §10.10. It is called after `offlineEarnings`.

**`forts.js`:** slots, costs, `build`, `upgrade`, `demolish` and effects, following the
`works.js` pattern with a `fortsEffects.js` leaf.

**`militia.js`:** `militiaGarrisons(state, world, regionId, nowMs) → number[]` per settlement,
and `drainMilitia(state, regionId, lost, nowMs)` after a defense.
